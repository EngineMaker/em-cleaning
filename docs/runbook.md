# 運用手順書 (Runbook)

## 1. 開発環境のセットアップ

1.  このリポジトリをクローンします。
2.  Node.js (v20以上) をインストールします。
3.  `npm install` を実行して、`clasp` などの開発ツールをインストールします。
4.  `npm run login` を実行し、Googleアカウントでログインします。

## 2. デプロイ手順

### 手動デプロイ

-   **住人管理GAS**: `npm run deploy:resident`
-   **掃除管理GAS**: `npm run deploy:cleaning`

### 自動デプロイ

`main`ブランチにマージされると、GitHub Actionsが自動的に両方のGASプロジェクトをデプロイします。

**注意**: 自動デプロイを有効にするには、リポジトリのGitHub Secretsに以下の情報を設定する必要があります。

-   `CLASPRC_ACCESS_TOKEN`
-   `CLASPRC_REFRESH_TOKEN`
-   `CLASPRC_EXPIRY_DATE`
-   各GASプロジェクトの `SCRIPT_ID`

## 3. 日常運用

### 3.1. 新規住人の入居

1.  **住人イベントフォーム**を開きます。
2.  **イベント種別**: `入居` を選択します。
3.  **対象の住人**: `（新規登録）` を選択します。
4.  新しい住人の氏名、ニックネーム、入居先の部屋、入居日を入力して送信します。
5.  GASが自動で `Residents` シートと `Occupancies` シートに新しい行を追加します。

### 3.2. 住人の退居

1.  **住人イベントフォーム**を開きます。
2.  **イベント種別**: `退居` を選択します。
3.  対象の住人、退居日を選択して送信します。
4.  GASが自動で対象住人の `Occupancies` シートの `end_date` を更新します。

### 3.3. 部屋移動

1.  **住人イベントフォーム**を開きます。
2.  **イベント種別**: `部屋移動` を選択します。
3.  対象の住人、移動先の部屋、移動日を選択して送信します。
4.  GASが自動で古い居住履歴の `end_date` を更新し、新しい居住履歴の行を追加します。

### 3.4. 掃除の記録

1.  **掃除記録フォーム**を開きます。
2.  掃除した日、部屋（またはドミトリーと住人）、掃除した場所を選択して送信します。
3.  GASが自動で `Cleanings` シートに記録します。

## 4. トラブルシューティング

### 4.1. フォームの選択肢が古い

**原因**: GASの`sync`トリガーが失敗したか、実行が遅れている可能性があります。
**対応**:
1.  Google Apps Scriptの管理画面を開きます。
2.  該当プロジェクト（`gas-resident` または `gas-cleaning`）のトリガー管理画面を確認します。
3.  `sync`関数を手動で実行して、フォームの選択肢を強制的に更新します。

### 4.2. データが正しく登録されない

**原因**: フォーム送信時のGAS処理（`log`関数）でエラーが発生している可能性があります。
**対応**:
1.  Google Apps Scriptの管理画面で、該当プロジェクトの「実行数」ログを確認します。
2.  失敗したプロセスのエラーメッセージを読み、原因を特定します。
3.  多くの場合、シートの列名が変更された、などのスキーマ不整合が原因です。コードまたはシートを修正し、必要であれば手動でデータを復旧します。

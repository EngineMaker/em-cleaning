# 仕様書: EngineMaker 掃除管理DX

## 1. 用語定義

| 用語 | 説明 |
| :--- | :--- |
| **ハウス (House)** | 複数のシェアハウスの拠点。`house_id`で管理される。 |
| **住人 (Resident)** | シェアハウスの住人。不変の`resident_id`で管理される。 |
| **部屋 (Room)** | いずれかのハウスに属する物理的な部屋。`room_id`で管理される。 |
| **居住 (Occupancy)** | 住人が特定の部屋にいつからいつまで住んでいるかを表す情報。 |
| **掃除場所 (Cleaning Place)** | いずれかのハウスに属する掃除の対象となる場所（タスク）。 |
| **掃除記録 (Cleaning)** | 「いつ」「誰が」「どこを」掃除したかの記録。 |
| **掃除回 (Cleaning Cycle)** | 掃除を管理する単位。通常は月単位（例: 2023-10）。 |

## 2. データモデル

Google Spreadsheetをデータベースとして利用する。

### 2.1. `Houses` シート

ハウスのマスタ情報。

| 列名 | 型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `house_id` | `String` | **[PK]** ハウスの不変ID | `house_a` |
| `house_name` | `String` | ハウスの名称 | `EngineMakerハウスA棟` |
| `created_at` | `Timestamp` | 作成日時 | `2023-10-01 09:00:00` |

### 2.2. `Residents` シート

住人のマスタ情報。

| 列名 | 型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `resident_id` | `String` | **[PK]** 住人の不変ID | `res_12345` |
| `name` | `String` | 実名 | `山田 太郎` |
| `nickname` | `String` | ニックネーム | `タロー` |
| `created_at` | `Timestamp` | 作成日時 | `2023-10-01 10:00:00` |

### 2.3. `Rooms` シート

部屋のマスタ情報。

| 列名 | 型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `room_id` | `String` | **[PK]** 部屋の不変ID | `a_101`, `b_d1` |
| `house_id` | `String` | **[FK]** `Houses`シートへの参照 | `house_a` |
| `room_label` | `String` | 表示用の部屋名 | `101号室`, `ドミトリー松` |
| `room_type` | `String` | 部屋の種別 | `個室`, `ドミトリー` |
| `created_at` | `Timestamp` | 作成日時 | `2023-10-01 10:00:00` |

### 2.4. `Occupancies` シート

住人の居住履歴。

| 列名 | 型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `occupancy_id` | `String` | **[PK]** 居住履歴ID | `occ_67890` |
| `resident_id` | `String` | **[FK]** `Residents`シートへの参照 | `res_12345` |
| `room_id` | `String` | **[FK]** `Rooms`シートへの参照 | `a_101` |
| `start_date` | `Date` | 居住開始日 | `2023-04-01` |
| `end_date` | `Date` | 居住終了日（NULL許容） | `2024-03-31` |

### 2.5. `CleaningPlaces` シート

掃除場所のマスタ。

| 列名 | 型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `place_id` | `String` | **[PK]** 掃除場所ID | `a_kit` |
| `house_id` | `String` | **[FK]** `Houses`シートへの参照 | `house_a` |
| `place_name` | `String` | 掃除場所の名称 | `キッチン` |
| `description` | `String` | 補足説明 | `コンロ周り、シンク、床` |

### 2.6. `Cleanings` シート

掃除の実施記録。

| 列名 | 型 | 説明 | 例 |
| :--- | :--- | :--- | :--- |
| `cleaning_id` | `String` | **[PK]** 掃除記録ID | `cln_abcde` |
| `cycle` | `String` | 掃除回（年月） | `2023-10` |
| `place_id` | `String` | **[FK]** `CleaningPlaces`への参照 | `a_kit` |
| `resident_id` | `String` | **[FK]** `Residents`への参照 | `res_12345` |
| `cleaned_at` | `Timestamp` | 掃除実施日時 | `2023-10-15 14:00:00` |

## 3. フォーム仕様

### 3.1. 掃除記録フォーム

*   **目的**: 住人が掃除した場所を記録する。
*   **質問項目**:
    1.  **ハウス**: `プルダウン` (必須)
        *   `Houses`シートから動的に取得。
        *   **分岐**: 以降の質問の選択肢が、ここで選ばれたハウスに絞られる。
    2.  **掃除した日**: `日付` (必須)
    3.  **部屋番号**: `プルダウン` (個室のみ)
        *   選択されたハウスの`Rooms`シートから`room_type`が`個室`のものを動的に取得。
        *   **分岐**: この質問に回答すると、住人名が自動確定。
    4.  **ドミトリー部屋**: `プルダウン` (ドミトリーのみ)
        *   選択されたハウスの`Rooms`シートから`room_type`が`ドミトリー`のものを動的に取得。
        *   **分岐**: この質問に回答すると、次の「住人名」の選択肢が絞られる。
    5.  **住人名（ドミトリー選択時）**: `プルダウン`
        *   前の質問で選ばれた部屋に、当日時点で在住している住人を動的に表示。
    6.  **掃除した場所**: `プルダウン` (複数選択可)
        *   選択されたハウスの`CleaningPlaces`シートから動的に取得。
        *   **入力チェック**:
            *   （推奨）過去2か月に自分が担当した場所には警告を表示。
            *   （必須）今回の掃除回で、すでに他の誰かが担当した場所は選択不可にするか、警告を表示。

### 3.2. 住人イベントフォーム

*   **目的**: 管理者が住人の入居・退居・部屋移動を登録する。
*   **質問項目**:
    1.  **ハウス**: `プルダウン` (必須)
        *   `Houses`シートから動的に取得。
        *   **分岐**: 以降の質問の選択肢が、ここで選ばれたハウスに絞られる。
    2.  **イベント種別**: `ラジオボタン` (必須)
        *   選択肢: `入居`, `退居`, `部屋移動`
        *   **分岐**: 選択に応じて後続の質問が変化。
    3.  **対象の住人**: `プルダウン`
        *   `Residents`シートから全住人を表示。新規の場合は「新規登録」を選択。
    4.  **氏名・ニックネームなど**: `テキスト` (新規登録時のみ)
    5.  **部屋**: `プルダウン`
        *   選択されたハウスの`Rooms`シートから部屋を表示。
    6.  **イベント発生日**: `日付` (必須)
        *   入居日、退居日、移動日など。未来日付の登録を許容する。

## 4. Apps Script (GAS) の責務分割

（責務の分割方針は変わりませんが、各機能で`house_id`を考慮する必要があります）

### 4.1. `packages/*-core` (ドメインロジック)

*   **責務**: Googleサービスに依存しない純粋なビジネスロジック。
*   **`resident-core`**:
    *   `Occupancy`の期間フィルタリング。
    *   `Resident`, `Room`, `House`の型定義。
*   **`cleaning-core`**:
    *   連続掃除の判定ロジック。
    *   未経験の掃除場所を計算するロジック。

### 4.2. `apps/gas-*` (アプリケーションロジック)

*   **責務**: Googleサービスと連携し、ドメインロジックを利用する。
*   **`gas-resident`**:
    *   **`sync`**: `Houses`, `Residents`, `Rooms`シートの情報を、フォームの選択肢に同期する（ハウスで絞り込み）。
    *   **`validate`**: `Occupancies`シートで期間の重複などがないか検証する。
    *   **`log`**: 住人イベントフォームからの送信をトリガーに、シートを更新し、`Logs`シートに記録する。
    *   **`query`**: 「特定の日付・ハウスの在住者一覧」などを返す関数。
*   **`gas-cleaning`**:
    *   **`sync`**: `CleaningPlaces`シートの情報を、掃除記録フォームの選択肢に同期する（ハウスで絞り込み）。
    *   **`validate`**: フォーム送信時に、重複担当ルールに抵触しないか検証する。
    *   **`log`**: 掃除記録フォームからの送信をトリガーに、`Cleanings`シートに記録する。
    *   **`query`**: 「個人の掃除履歴」「場所ごとの掃除履歴」などを返す関数（ハウスで絞り込み可）。
